# Infraestrutura AWS — EC2

## 1. Objetivo

Este documento descreve a criação da primeira instância Amazon EC2
utilizada no projeto **Sistema Escolar**.

Após a configuração da camada de rede e do Security Group, foi criada
uma máquina virtual para hospedar a aplicação.

Nesta primeira implementação, a configuração da instância será realizada
manualmente.

O objetivo é compreender todo o processo de preparação de um servidor
Linux antes de automatizar essa etapa.

---

# 2. O que é Amazon EC2?

Amazon EC2 (Elastic Compute Cloud) é um serviço de computação da AWS
que permite criar e executar servidores virtuais na nuvem.

Uma instância EC2 pode executar:

- sistema operacional;
- servidor web;
- aplicação;
- scripts;
- serviços;
- ferramentas administrativas.

No projeto Sistema Escolar, a EC2 será inicialmente responsável por
executar a aplicação web desenvolvida em Python.

---

# 3. Configuração da instância

A primeira instância foi criada com as seguintes características:

- **Nome:** `sistema-escolar-ec2`
- **Sistema operacional:** Amazon Linux 2023
- **Tipo da instância:** `t3.micro`
- **Quantidade:** 1 instância
- **Armazenamento:** 8 GiB
- **Tipo do volume:** `gp3`
- **VPC:** `sistema-escolar-vpc`
- **Subnet:** `sistema-escolar-public-subnet-1a`
- **Security Group:** `sistema-escolar-sg`
- **IP público automático:** habilitado
- **Key Pair:** configurado
- **User Data:** não utilizado nesta primeira versão

---

# 4. Escolha do Amazon Linux 2023

## O que é uma AMI?

AMI significa:

**Amazon Machine Image**

Uma AMI funciona como uma imagem utilizada como base para a criação
da instância EC2.

Ela pode determinar, entre outras características, qual sistema
operacional será instalado no servidor.

## Escolha realizada

Foi utilizado:

`Amazon Linux 2023`

## Por que Amazon Linux?

O Amazon Linux é uma distribuição Linux mantida pela AWS e integrada
ao ecossistema da plataforma.

Para esta primeira instância, ele permite estudar:

- administração Linux;
- gerenciamento de pacotes;
- acesso SSH;
- configuração de serviços;
- instalação do ambiente Python;
- preparação de uma aplicação para execução em servidor.

Também foi decidido utilizar futuramente uma segunda instância baseada
em Ubuntu para comparar os dois ambientes.

---

# 5. Tipo da instância — t3.micro

## O que é o tipo da instância?

O tipo da instância determina os recursos computacionais disponíveis
para a máquina virtual.

Entre eles:

- CPU;
- memória;
- desempenho de rede;
- características da família da instância.

## Configuração utilizada

Foi selecionado:

`t3.micro`

Essa configuração é suficiente para o estágio atual do projeto,
que possui uma aplicação web pequena e baixa carga de usuários.

## Por que não utilizar uma instância maior?

O objetivo atual é desenvolvimento, laboratório e aprendizado.

Não existe necessidade de provisionar recursos de computação maiores
antes de existir uma demanda real.

Essa decisão segue um princípio importante de arquitetura:

> Provisionar recursos de acordo com a necessidade atual e aumentar
> a capacidade quando houver demanda.

Em uma aplicação real, métricas de utilização poderiam ser utilizadas
para decidir se a instância precisa ser redimensionada.

---

# 6. Armazenamento EBS

A instância possui um volume:

- **Capacidade:** 8 GiB
- **Tipo:** `gp3`

## O que é EBS?

Amazon EBS (Elastic Block Store) fornece armazenamento em bloco para
instâncias EC2.

De maneira simplificada, o volume EBS funciona como o disco do servidor.

Nele serão armazenados:

- sistema operacional;
- aplicação;
- bibliotecas;
- configurações;
- arquivos do servidor;
- logs.

## Por que 8 GiB?

Para o laboratório atual, 8 GiB são suficientes para executar o sistema
operacional e os componentes necessários para a aplicação.

Não existe necessidade de provisionar um volume maior antes que exista
demanda por mais armazenamento.

---

# 7. Sistema de arquivos adicional

Durante a criação da EC2, a AWS apresentou opções adicionais como:

- Amazon S3;
- Amazon EFS;
- Amazon FSx.

Nenhum sistema de arquivos adicional foi configurado nesta etapa.

## Por quê?

A instância já possui um volume EBS suficiente para o laboratório.

Serviços como EFS são úteis, por exemplo, quando múltiplos servidores
precisam acessar um armazenamento compartilhado.

S3 possui outro modelo de armazenamento, baseado em objetos, e poderá
ser utilizado futuramente caso a aplicação necessite armazenar arquivos.

Adicionar esses serviços agora aumentaria a complexidade sem resolver
uma necessidade existente.

# 9. IP público automático

Durante a criação da instância foi habilitada a opção:

`Auto-assign Public IP`

## Por que habilitamos?

A instância está localizada em uma subnet pública e será acessada
externamente.

Nesta primeira etapa, também utilizaremos SSH a partir da máquina
do administrador.

Para que uma instância seja acessível diretamente através da internet,
ela precisa possuir um endereço IP público, além das configurações
corretas de roteamento e segurança.

O caminho completo envolve:

Internet
   |
   v
IP público da EC2
   |
   v
Internet Gateway
   |
   v
Route Table
   |
   v
Subnet pública
   |
   v
Security Group
   |
   v
EC2

## Observação

O endereço IPv4 público atribuído automaticamente à EC2 pode mudar
após um ciclo de interrupção e inicialização da instância.

Portanto, antes de realizar uma nova conexão SSH, é importante
verificar o endereço público atual.

# 10. Key Pair — Par de chaves

Durante a criação da EC2 foi configurado um Key Pair.

A chave privada foi disponibilizada no formato:

`.pem`

## Para que serve?

O par de chaves é utilizado para autenticação durante o acesso SSH.

De maneira simplificada, existem duas partes:

- chave pública;
- chave privada.

A AWS instala a chave pública correspondente na instância.

A chave privada permanece sob responsabilidade do administrador.

Quando uma conexão SSH é realizada, a chave privada é utilizada
para comprovar que o usuário possui a credencial correspondente.

---

# 11. Por que proteger o arquivo .pem?

O arquivo `.pem` é uma credencial de acesso.

Ele não deve ser:

- enviado para outras pessoas;
- publicado no GitHub;
- armazenado dentro do repositório;
- incluído em commits.

O arquivo deve permanecer protegido na máquina do administrador.

> Nunca versionar chaves privadas no Git.

Caso necessário, o arquivo `.gitignore` do projeto deve garantir
que arquivos `.pem` não sejam adicionados acidentalmente ao repositório.

---

# 12. Relação entre Key Pair e IP público

O endereço IP público e o Key Pair possuem funções diferentes.

O IP responde:

> Onde está o servidor?

A chave responde:

> Quem está autorizado a se autenticar?

Portanto, caso o IP público da EC2 mude, a chave privada não precisa
ser baixada novamente.

A mesma chave continua associada ao mecanismo de autenticação
configurado na instância.

# 13. User Data

Durante a criação da EC2 existe uma opção chamada:

`User Data`

Ela permite fornecer comandos ou scripts que podem ser executados
durante a inicialização da instância.

Isso possibilita automatizar tarefas como:

- atualização do sistema;
- instalação do Python;
- instalação de dependências;
- instalação de servidores web;
- criação de arquivos;
- preparação do ambiente da aplicação.

## Por que não utilizamos User Data nesta instância?

A decisão foi proposital.

Nesta primeira EC2, toda a configuração será realizada manualmente.

O objetivo é aprender:

1. conectar ao servidor;
2. utilizar Linux;
3. atualizar o sistema;
4. instalar pacotes;
5. instalar dependências;
6. configurar a aplicação;
7. executar e validar os serviços.

Somente depois de entender o processo manual será criada uma versão
automatizada.

# 15. Start, Stop e Terminate

Durante os estudos é importante diferenciar três operações.

## Start

Inicializa uma instância que estava interrompida.

A máquina volta a executar normalmente.

## Stop

Interrompe a execução da instância sem necessariamente destruir
o servidor e seu volume EBS.

Isso permite continuar o laboratório posteriormente sem reconstruir
todo o ambiente.

## Terminate

Encerra a instância.

Essa operação é diferente de simplesmente desligar o servidor e pode
resultar na remoção definitiva da instância e, dependendo da configuração,
de volumes associados.

Portanto:

`Stop ≠ Terminate`

Para o laboratório, a estratégia adotada é interromper a instância
quando ela não estiver sendo utilizada e iniciá-la novamente quando
os estudos continuarem.

---

# 16. Recursos associados à instância

Interromper uma EC2 não significa necessariamente que todos os recursos
associados deixam de existir.

Por exemplo, o volume EBS continua existindo enquanto estiver associado
e preservado.

Também é importante conhecer recursos como Elastic IP, caso sejam
utilizados futuramente.

Por isso, gerenciamento de custos em cloud não envolve apenas observar
se uma máquina virtual está ligada ou desligada.

É necessário conhecer os recursos associados à arquitetura.

# 18. Decisões de arquitetura

## Amazon Linux 2023

**Decisão:** utilizar Amazon Linux na primeira EC2.

**Motivo:** aprender administração de um servidor Linux dentro do
ecossistema AWS.

---

## t3.micro

**Decisão:** utilizar uma instância pequena.

**Motivo:** a aplicação ainda está em ambiente de laboratório e não
necessita grande capacidade computacional.

---

## EBS gp3 de 8 GiB

**Decisão:** manter armazenamento inicial reduzido.

**Motivo:** suficiente para o estágio atual da aplicação, evitando
provisionamento desnecessário.

---

## IP público

**Decisão:** habilitar atribuição automática de IPv4 público.

**Motivo:** permitir acesso externo à primeira EC2 do laboratório.

---

## SSH com Key Pair

**Decisão:** utilizar autenticação por chave para administração remota.

**Motivo:** aprender o funcionamento do acesso SSH à EC2 e evitar
autenticação baseada simplesmente em senha.

---

## Configuração manual

**Decisão:** não utilizar User Data nesta primeira instância.

**Motivo:** compreender cada etapa da preparação do servidor antes
de automatizar o processo.
